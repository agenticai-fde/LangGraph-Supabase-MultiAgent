# Supabase Multi-Agent (CRUD) with LangGraph + Ollama

A terminal chat app where a **supervisor agent** reads your request and hands it to
one of four specialist agents that **create, read, update or delete** rows in a
Supabase table. Everything runs locally except the database.

- **LLM:** Ollama (local, default `qwen2.5:7b`)
- **Orchestration:** LangGraph
- **Agents:** LangChain `create_agent`
- **Database:** Supabase (`enterprise_customer_operations` table)

---

## Architecture

```
                        You type a request
                               |
                               v
                 +----------------------------+
                 |        SUPERVISOR          |
                 |  (LLM picks one route)     |
                 +----------------------------+
                               |
            LangGraph conditional edge (choose_next_step)
                               |
          +---------+----------+----------+----------+
          |         |          |          |          |
          v         v          v          v          v
      +-------+ +-------+  +--------+ +--------+ +--------+
      |CREATE | | READ  |  | UPDATE | | DELETE | | FINISH |
      | agent | | agent |  | agent  | | agent  | | (chat) |
      +-------+ +-------+  +--------+ +--------+ +--------+
          |         |          |          |          |
     create_   read_     update_    delete_       no tools,
     record    records   record     record        no database
          |         |          |          |
          |         |          |    asks YOU to type
          |         |          |    the ID to confirm
          +---------+----------+----------+
                         |
                         v
              +----------------------+
              |  Supabase (Postgres) |
              |  enterprise_customer |
              |     _operations      |
              +----------------------+
```

Each agent gets **only the one tool it needs**, so for example the READ agent
cannot delete anything. Deletes need a human to type the record ID in the
terminal; the LLM cannot approve a delete by itself.

In LangGraph terms the graph is:

```
START -> supervisor -> (agent | finish) -> END
```

## Project structure

```
supabase_multiagent/
├── app.py            all the code (settings, tools, agents, graph, chat loop)
├── .env              your settings and keys (never commit this)
├── .env.example      template for .env
├── requirements.txt  Python packages
└── .gitignore
```

`app.py` is split into numbered steps:

| Step | What it does |
|---|---|
| 1 | Loads settings from `.env` |
| 2 | Connects to Ollama and Supabase |
| 3 | Database tools: `create_record`, `read_records`, `update_record`, `delete_record` |
| 4 | Builds the four agents |
| 5 | LangGraph workflow: `supervisor` → `run_agent` / `general_chat` |
| 6 | Terminal chat loop (`main`) |

## Step 1: Create the table in Supabase

1. Sign in at <https://supabase.com/dashboard> and open your project
   (or click **New project** to create one).
2. In the left sidebar click **SQL Editor** → **New query**.
3. Paste the SQL below and click **Run**.

### 1a. Create the table

```sql
-- Table that the agents read and write
create table if not exists public.enterprise_customer_operations (
    id                  bigint generated by default as identity primary key,
    customer_name       text not null,
    company_name        text,
    email               text unique,
    industry            text,
    service_type        text,
    request_description text,
    priority            text default 'medium',       -- low | medium | high | critical
    assigned_team       text,
    account_status      text default 'active',       -- active | inactive
    resolution_status   text default 'open',         -- open | in_progress | resolved
    contract_value      numeric(12, 2) default 0,
    created_at          timestamptz default now(),
    updated_at          timestamptz default now()
);

-- Keep updated_at current on every UPDATE
create or replace function public.touch_updated_at()
returns trigger
language plpgsql
as $$
begin
    new.updated_at := now();
    return new;
end $$;

drop trigger if exists trg_eco_updated_at on public.enterprise_customer_operations;
create trigger trg_eco_updated_at
    before update on public.enterprise_customer_operations
    for each row execute function public.touch_updated_at();

-- Row Level Security: blocks the public (publishable) key.
-- The app uses the SECRET key, which bypasses RLS.
alter table public.enterprise_customer_operations enable row level security;
```

## Step 2: Get your Supabase URL and secret key

1. In the dashboard go to **Project Settings** (gear icon) → **API Keys**.
2. Copy the **secret key** (starts with `sb_secret_`). Click **Reveal** if hidden.
3. Your **project URL** is `https://<project-ref>.supabase.co`. The project ref
   is the ID in your dashboard address: `supabase.com/dashboard/project/<project-ref>`.

> **Keep the secret key private.** It can read and change every table and
> bypasses Row Level Security. Never commit it, paste it in chat, or use it in
> browser code. If it leaks, roll it on the same API Keys page.

## Step 3: Install and run

Open a terminal (PowerShell on Windows) in this folder.

### 3a. Get the model

```powershell
ollama pull qwen2.5:7b
```

Ollama usually runs in the background after install. If not, run `ollama serve`
in a separate terminal.

### 3b. Create a virtual environment and install packages

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

macOS / Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

### 3c. Configure `.env`

```powershell
copy .env.example .env
```

Edit `.env`:

```env
SUPABASE_URL=https://<project-ref>.supabase.co
SUPABASE_KEY=sb_secret_xxxxxxxxxxxxxxxxxxxxxxxx

SUPABASE_TABLE=enterprise_customer_operations

OLLAMA_MODEL=qwen2.5:7b
OLLAMA_BASE_URL=http://localhost:11434
```

### 3d. Run

```powershell
.venv\Scripts\python.exe app.py
```

(macOS / Linux: `.venv/bin/python app.py`)

Type `exit` to quit.

## Prompts to try

| Agent | Prompt |
|---|---|
| READ | `Show all open high priority requests` |
| READ | `Show record 4` |
| CREATE | `Create a request for customer Test Agent at company Demo Test Ltd, email test.agent@example.com, industry IT, service type Technical Support, request description Login page not loading, priority low, assigned team Technical Team` |
| UPDATE | `Update record 3 resolution status to in_progress` |
| UPDATE | `Update record 2 priority to high` |
| DELETE | `Delete record 12` (then type `12` to confirm, anything else cancels) |
| FINISH | `Hello, what can you do?` |

Allowed values (the tools reject anything else):

- **priority:** `low`, `medium`, `high`, `critical`
- **resolution_status:** `open`, `in_progress`, `resolved`
- **account_status:** `active`, `inactive`

## Troubleshooting

| Problem | Fix |
|---|---|
| `Please set SUPABASE_URL and SUPABASE_KEY` | `.env` is missing or not in this folder. |
| `Read failed ... permission denied` / empty results | You used the publishable key. Use the **secret** key. |
| `Create failed ... duplicate key ... email` | Each email must be unique. Use a new one. |
| `Connection refused` on port 11434 | Ollama isn't running. Start it with `ollama serve`. |
| `model "qwen2.5:7b" not found` | Run `ollama pull qwen2.5:7b`. |
| Replies take minutes | The model is running on CPU. Close other apps, or set `OLLAMA_MODEL=llama3.2` in `.env` (faster, but less reliable at choosing tools). |
| Wrong agent picked | Start the request with the action word: *show*, *create*, *update*, *delete*. |
